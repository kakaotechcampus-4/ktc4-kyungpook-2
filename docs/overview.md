# 서비스 개요

잇다가 무엇을 하는지, 누가 쓰는지, 일이 어떤 순서로 흐르는지를 한 장에 담습니다.
도메인마다 자세한 규칙은 `docs/domains/`의 문서에 있습니다.

---

## 잇다가 하는 일

한 아이가 학교 · 발달센터 · 활동보조 기관을 함께 다니면 기록도 기관마다 따로 쌓입니다.
잇다는 기관이 올린 관찰일지를 AI가 아이별로 나누고, 걸러 내고, 요약한 뒤, **선생님이 승인한 것만** 보호자에게 전합니다.
여러 기관의 기록에서 반복되는 모습은 주간 인사이트로 묶고, 보호자가 고른 기관끼리 나눠 봅니다.

---

## 누가 쓰나

| 역할 | 누구 | 하는 일 |
| --- | --- | --- |
| **기관** | 기관 담당자(선생님). 기관 하나에 계정 하나 | 아이 등록 · 일지 업로드 · AI가 묻는 기록 확인 · 1차 · 2차 검토 · 준비물 보내기 |
| **보호자** | 아이의 부모 등 | 초대 코드로 아이와 연결 · 기관마다 공유 동의 · 일지와 리포트 보기 · 다른 기관에 인사이트 공유 |

기관 종류는 셋입니다 — 학교 · 발달센터 · 활동보조.
두 역할 모두 카카오로 로그인하고, 처음 로그인할 때 역할을 고릅니다. 역할은 바꿀 수 없습니다.

---

## 전체 흐름

```
① 연결        기관이 아이 등록 → 초대 코드 → 보호자가 수락 → 보호자가 기관마다 동의
               (다른 기관은 보호자가 기관 코드로 연결 요청 → 그 기관이 수락)

② 기록        일지 파일 업로드 → 매칭(누구 기록인가) → 검증(그대로 둬도 되나) → 요약(하루치 한 편)
               ↳ AI가 판단하기 어려운 기록만 선생님 확인으로

③ 1차 검토    선생님이 하루 요약을 고치고 승인 → 보호자 일지에 보임

④ 인사이트    승인된 요약을 한 주 단위로 겹쳐, 여러 기관에 걸친 패턴을 찾음 (동의한 기관 기록만)

⑤ 2차 검토    선생님이 인사이트를 승인 → 보호자 리포트에 보임 · 보호자에게 메일
               → 보호자가 고른 다른 기관의 수신함에 열림
```

- 사람이 결정하는 자리는 ③ · ⑤ 두 곳입니다. 나머지는 백엔드 워커가 스스로 일을 집어 AI에 보냅니다
- 보호자는 **선생님이 승인한 것**만 봅니다. 기관은 보호자가 동의하거나 공유한 것만 봅니다
- 따로 흐르는 기능: 기관이 보호자에게 **준비물 · 확인사항**을 보내고 보호자가 확인합니다

## 도메인 지도

| 도메인 | 다루는 것 | 주요 API (`backend/.../api`) |
| --- | --- | --- |
| [계정](domains/account.md) | 로그인 · 가입 · 약관 · 탈퇴 · 기관 담당자 넘기기 | `Auth` · `Terms` · `DevLogin` · `KakaoWebhook` · `Organization` |
| [아이 · 보호자](domains/child-guardian.md) | 아이 등록 · 초대 코드 · 보호자 연결 · 기관 코드 연결 요청 · 돌봄 정보 | `Child` · `Invitation` · `Guardian` · `ChildGuardian` · `InstitutionLink` · `LinkRequest` · `ChildCareInfo` |
| [동의](domains/consent.md) | 기관마다 무엇을 공유할지, 동의를 거두면 무엇이 사라지나 | `Consent` |
| [기록](domains/records.md) | 업로드 · 매칭 · 검증 · 요약, AI가 묻는 기록 확인 | `RawRecord` · `MatchingQueue` · `ValidationResult` |
| [검토](domains/review.md) | 1차 검토(요약) · 인사이트 · 2차 검토 | `Summary` · `Insight` |
| [공유](domains/sharing.md) | 보호자 일지 · 리포트 · 메일 · 다른 기관 수신함 | `GuardianJournal` · `GuardianInsight` · `InstitutionInbox` |
| [준비물 · 확인사항](domains/checklist.md) | 기관이 보내고 보호자가 확인 | `Checklist` · `GuardianChecklist` |
| [대시보드](domains/dashboard.md) | 처리 현황 · 아이 타임라인 · AI 상태 | `Dashboard` · `OrganizationTimeline` · `System` · `Health` |

AI가 각 단계에서 어떻게 판단하는지는 [AI/README.md](../AI/README.md), 테이블은 [db/schema.md](db/schema.md)에 있습니다.

## 용어

| 용어 | 뜻 |
| --- | --- |
| 기관 | 아이가 다니는 학교 · 발달센터 · 활동보조 기관. 코드에서는 `organization` (API 경로는 `institutions`) |
| 명부 | 기관에 등록된 아이 목록. 매칭은 명부 안에서만 아이를 찾습니다 |
| 초대 코드 | 기관이 아이를 등록하면 나오는 10분짜리 일회용 코드. 보호자가 입력해 아이와 연결합니다 |
| 기관 코드 | 기관마다 하나 있는 코드. 이미 연결된 아이를 다른 기관에 붙일 때 보호자가 씁니다 |
| 원본 기록 | 기관이 올린 파일 하나 (`raw_record`) |
| 일지 | 원본 기록에서 나눈 기록 한 건 (`journal_entry`). 매칭 · 검증은 일지 단위로 돕니다 |
| 요약 | 같은 아이 · 같은 날 · 같은 기관의 일지를 묶은 한 편 (`summary_result`) |
| 1차 검토 | 선생님이 요약을 고치고 승인하는 단계. 코드에서는 Gate 1 |
| 인사이트 | 승인된 요약을 한 주 단위로 겹쳐 찾은 돌봄 패턴 (`insight_result`) |
| 2차 검토 | 선생님이 인사이트를 승인하거나 보류하는 단계. 코드에서는 Gate 2 |
| 수신함 | 보호자가 공유한 다른 기관의 인사이트가 열리는 곳 |
| 준비물 · 확인사항 | 기관이 보호자에게 보내는 알림. 보호자가 확인을 누릅니다 |
