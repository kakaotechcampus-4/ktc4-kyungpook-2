# 동의 — 기관마다 무엇을 공유하나

보호자가 아이의 기록을 기관마다 쓰게 할지 정합니다. 기록 처리 · 검토 · 공유가 모두 이 동의를 봅니다.

---

## 단위

- **아이 × 기관마다 하나**입니다. 보호자가 여럿이면 **한 명만 동의해도** 그 기관에 켜집니다
- 공유 항목은 둘입니다 — **하루 요약**(`daily_summary`) · **주간 인사이트**(`weekly_insight`)
- 항목은 기관 단위로 하나라, **마지막으로 동의한 보호자의 항목**이 그 기관 전체에 적용됩니다
- 철회는 그 기관에 대한 **모든 보호자의 동의**를 끕니다

---

## 동의가 바꾸는 것

| | 동의 있음 | 주간 인사이트 동의 있음 |
| --- | --- | --- |
| 매칭 | 그 기관 명부에서 후보가 됩니다 | |
| 1차 검토 | 그 기관 목록에 요약이 보입니다 | |
| 자동 요약 | 그 기관 묶음을 요약합니다 | |
| 인사이트 재료 | | 그 기관의 승인된 요약이 재료가 됩니다 |
| 인사이트 받기 | | 2차 승인 때 그 기관 수신함에 열립니다 |

지금 코드는 "하루 요약" 항목을 따로 검사하지 않습니다. 동의가 살아 있는지만 봅니다.

**아이 상태**도 동의로 정해집니다 — 동의가 한 번도 없으면 `PENDING_CONSENT`, 살아 있는 동의가 하나라도 있으면 `ACTIVE`, 모두 꺼졌으면 `SUSPENDED`.

---

## 철회하면

- **앞으로의 처리가 멈춥니다.** 그 기관에서 이 아이는 매칭 후보에서 빠지고, 1차 검토 목록에서도 빠집니다
- **그 기관이 받은 인사이트의 열람 권한을 거둡니다**
- **그 기관 기록이 재료가 된 인사이트는**, 다른 기관에 열어 준 열람 권한도 거둡니다
- 그 기관 기록이 재료인 **승인 전 인사이트는 2차 승인을 할 수 없습니다**
- 보호자가 이미 본 승인된 일지 · 인사이트는 보호자에게 그대로 남습니다

동의가 꺼지는 경우는 셋이고, 사유가 남습니다.

| 사유 | 언제 |
| --- | --- |
| `GUARDIAN_REVOKED` | 보호자가 직접 끔. 주간 인사이트 항목만 빼도 해당합니다 |
| `GUARDIAN_UNLINKED` | 보호자가 아이와 연결을 끊음. 그 보호자의 동의와 인사이트 열람 권한이 함께 꺼집니다 |
| `ROSTER_REMOVED` | 기관이 명부에서 아이를 뺌 |

---

## 보호자에게 동의를 묻는 때

아이가 기관 명부에 올라 있는데 **아직 아무도 동의하지 않은 기관**이 있으면, 보호자 화면에 알림 점 · 홈 배너 · 알림으로 뜹니다.

- 다른 보호자가 이미 동의한 기관은 뜨지 않습니다
- 동의했다가 끈 기관도 뜨지 않습니다. 보호자가 직접 끈 것이라 다시 묻지 않습니다

## API · 테이블 · 코드

**API** (`/api/v1/children/{childId}`, 보호자만)

- `GET /consent-preview` — 동의 화면에 그릴 아이 · 기관 · 공유 범위 (저장하지 않음)
- `PUT /consent-scopes/{institutionId}` — 동의 부여(`grant` + 항목) · 철회(`revoke`)
- `GET /institution-requests/pending` — 아직 동의를 기다리는 기관

**테이블** — `sharing_consent` (보호자 × 아이 × 기관, 철회 사유 · 시각) · `sharing_history` (인사이트 열람 권한) ([db/schema.md](../db/schema.md))

**코드** — `backend/.../service/consent` (`ConsentService` · `ConsentStateReader`) · `service/insight/InsightAccessRevoker.java` (열람 권한 회수)
