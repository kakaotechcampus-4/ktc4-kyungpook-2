# 검토 — 1차 검토 · 인사이트 · 2차 검토

요약이 1차 검토에 오른 뒤부터 인사이트가 승인되기까지입니다. 그 앞은 [기록](records.md), 승인 뒤 누가 보는지는 공유 도메인입니다.

---

## 흐름

```
요약 ─→ [1차 검토] ─→ 아동 맥락 ─→ 인사이트 (주 단위) ─→ [2차 검토] ─→ 보호자 · 다른 기관 · 메일
         선생님 승인     보호자 일지에 보임                    선생님 승인
```

사람이 결정하는 자리는 두 곳뿐입니다. 승인한 것만 다음 단계의 재료가 되고, 보호자에게 보입니다.

---

## 1. 1차 검토 — 하루 요약

기관마다 **자기 기관이 올린 일지의 요약**만 검토합니다. 오래된 날짜부터 보입니다.

선생님이 보는 것:

- 요약 본문과 문장 카드, 문장마다 근거가 된 일지
- 요약에 들어가지 않은 일지와 원문
- 검증 `REVIEW` 사유, 다른 아이 이름이 남았다는 경고

| 결정 | 무엇 | 되돌리기 |
| --- | --- | --- |
| 승인 | 그대로 승인. 문장 카드로 문장마다 유지 · 수정 · 삭제 · 추가하면 "수정 후 승인" | 안 됨 |
| 보류 | 보류함으로. 보류함에서 해제하면 다시 검토 대기 | 해제 가능 |
| 제거 | 요약과 일지를 모두 삭제 표시. 30일 뒤 원본까지 지웁니다 | 안 됨 |

- **승인하면** 그 요약의 일지가 모두 완료되고, 남은 문장을 이은 글이 **아동 맥락**에 올라갑니다. 보호자 일지에 보이고 인사이트의 재료가 됩니다
- 쓸 관찰 사실이 없던 **빈 요약**은 "확인"(완료, 아동 맥락에는 안 올라감)과 "되돌리기"(일지를 요약 전으로)만 받습니다
- 목록을 본 뒤 새 일지가 들어와 요약이 바뀌었으면 결정이 거절됩니다(409). 목록을 다시 받아 봅니다
- 보호자가 그 기관 동의를 거둔 아이의 요약은 목록에서 빠집니다

## 2. 인사이트 — 주 단위 패턴

인사이트 워커가 아이마다 **한 주(월 ~ 일)** 의 승인된 요약을 겹쳐 AI에 보냅니다.

- **재료** — 그 주에 승인된 요약 중, 보호자가 **주간 인사이트에 동의한 기관**의 것만. 지난 12주 기록도 함께 보내 AI가 도구로 찾아볼 수 있게 합니다
- **언제** — 끝난 주만 만듭니다. 최근 14일 안에 승인이 있었던 주를 봅니다 (`INSIGHT_INCLUDE_CURRENT_WEEK`를 켜면 이번 주도 — 시연용)
- **다시 만들기** — 만든 뒤 그 주에 승인이 더 들어오면 다음 회차로 다시 만듭니다. 검토 목록에는 최신 회차만 보입니다
- **실패하면** 1분 · 5분 · 30분 간격으로 다시 시도합니다
- 인사이트가 0건인 주도 정상입니다

## 3. 2차 검토 — 인사이트 승인

**승인 주체는 근거를 낸 기관 중 하나입니다.** 기관 종류 순서(학교 > 센터 > 활동보조, 같으면 작은 기관 번호)로 정해지고, 그 기관 목록에만 보입니다.

| 결정 | 무엇 | 되돌리기 |
| --- | --- | --- |
| 승인 | 보호자와 다른 기관에 열람 권한이 생깁니다 | 안 됨 |
| 보류 | 아무에게도 보이지 않습니다 | 안 됨 (1차 검토와 달리 해제 없음) |

**승인하면**

- 연결된 **보호자 모두**에게 열람 권한이 생깁니다. 보호자가 없으면 승인은 되지만 아무에게도 보이지 않습니다
- 아이가 다니는 **다른 기관 중 보호자가 주간 인사이트에 동의한 곳**의 수신함에 열립니다
- 알림 워커가 아이 × 주 단위로 승인된 인사이트를 묶어 보호자에게 **메일**을 보냅니다. 다른 아이 이름이 섞이면 보내지 않습니다. 같은 주에 새로 승인되면 다시 보냅니다

## 상태

| 대상 | 상태 |
| --- | --- |
| 요약 | `GATE1_PENDING` 검토 대기 → `APPROVED` 승인 · `CONFIRMED` 빈 요약 확인 · `HOLD` 보류 · `REMOVED` 제거 · `REVERTED` 되돌림 |
| 일지 | `GATE1_PENDING` → `COMPLETED` (승인 · 확인) · `GATE1_HELD` (보류) · `VALIDATED` (되돌림) |
| 인사이트 실행 | `RUNNING` → `DONE` · `FAILED` |
| 인사이트 | `GATE2_PENDING` → `APPROVED` · `HOLD` |
| 메일 | `RUNNING` → `SENT` · `NO_RECIPIENT` · `BLOCKED` (다른 아이 이름) · `FAILED` |

결정은 모두 `human_review`에 누가 · 언제 · 무엇을 했는지 남습니다.

## API · 테이블 · 코드

**API** (`/api/v1`, 기관 담당자만)

- `/summaries` — 1차 검토 목록(`gate1Status=pending`) · 보류함(`hold`) · 결정(`/{id}/gate1`) · 보류 해제(`/{id}/reopen`)
- `/insights` — 2차 검토 목록 · 단건 · 결정(`/{id}/gate2`)

요청 · 응답 필드는 Swagger에 있습니다.

**테이블** — `summary_result` · `child_context`(아동 맥락) · `human_review` · `insight_run` · `insight_result` · `sharing_history` · `insight_notification` ([db/schema.md](../db/schema.md))

**코드** — `backend/.../service/approval` (1차 검토) · `service/insight` (인사이트 워커 · 2차 검토) · `service/notify` (메일) · AI 쪽은 [AI/README.md](../../AI/README.md)
