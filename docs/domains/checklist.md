# 준비물 · 확인사항 — 기관이 보내고 보호자가 확인

기관이 보호자에게 "내일 실내화 챙겨 주세요" 같은 짧은 요청을 보내고, 보호자가 확인을 누릅니다.
AI와 검토를 거치지 않는 따로 흐르는 기능입니다.

---

## 흐름

```
기관이 보냄 ─→ 보호자 화면에 뜸 ─→ 보호자 중 한 명이 확인 ─→ 기관 목록에 누가 · 언제 확인했는지
     │
     └─ 기관이 내리면 모두에게서 사라짐
```

---

## 기관 — 보내기

- 명부의 아이들을 골라 **항목 1~10줄**(줄마다 100자)을 한 번에 보냅니다
- 받는 아이는 **보낸 순간의 명부**로 정해집니다. **공유 동의와는 상관없습니다**
- 보낸 뒤에는 고칠 수 없고 **내리기**만 할 수 있습니다. 내리면 받은 아이 모두에게서 통째로 사라지고, 이미 남은 확인 기록은 지우지 않습니다
- 보낸 목록에서 아이별 확인 여부와 확인한 보호자를 봅니다. 명부에서 빠진 아이는 확인 집계에서 빠집니다

## 보호자 — 확인

- 확인 안 한 요청 전부가 먼저, 그 뒤에 확인한 요청 최근 20개가 보입니다. 확인 안 한 개수는 알림 벨과 설정 화면에 씁니다
- **보호자 중 한 명이 확인하면 끝**이고 되돌리지 않습니다. 다른 보호자가 이미 확인했으면 그 확인(누가 · 언제)을 보여 줍니다
- 기관이 내린 요청, 아이가 그 기관 명부에서 빠진 요청은 보이지 않습니다

## API · 테이블 · 코드

**API** (`/api/v1`)

- 기관: `/institutions/me/checklists` — 보내기 · 보낸 목록(최신순 50개씩) · 내리기(`/{checklistId}`)
- 보호자: `/children/{childId}/checklists` — 받은 목록(`status=needs_check`면 확인 안 한 것만) · 확인(`/{checklistId}/confirm`)

**테이블** — `checklist` (보낸 요청 · 내린 시각) · `checklist_target` (받은 아이 · 확인한 보호자 · 시각) ([db/schema.md](../db/schema.md))

**코드** — `backend/.../service/checklist`
