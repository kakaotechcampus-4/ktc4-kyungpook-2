# 기록 — 업로드 · 매칭 · 검증 · 요약

기관이 올린 일지 파일이 1차 검토에 오르기까지입니다. 용어는 [overview.md](../overview.md#용어)를 따릅니다.

---

## 흐름

```
파일 업로드 ─→ 일지로 나누기 ─→ 매칭 ─→ 검증 ─→ 요약 ─→ 1차 검토 (검토 도메인)
                                │        │       │
                                ↓        ↓       ↓
                       누구 것인지 확인  막힌 표현 고치기  요약 실패 처리
                       (선생님)        (선생님)        (선생님)
```

- 매칭 · 검증 · 요약은 백엔드 워커가 5초마다 일을 집어 AI 서버에 보냅니다. 선생님이 누르지 않습니다
- 선생님에게 오는 것은 AI가 판단하기 어려운 기록뿐입니다
- AI가 각 단계에서 어떻게 판단하는지는 [AI/README.md](../../AI/README.md)에 있습니다

---

## 1. 업로드

브라우저가 파일을 저장소(운영은 S3)에 바로 올립니다. 백엔드는 주소와 권한만 내줍니다.

1. `POST /raw-records/upload-url` — 이름 · 형식 · 크기를 확인하고 업로드 주소를 받습니다
2. 받은 주소로 파일을 올립니다
3. `POST /raw-records/uploads/{uploadId}/complete` — 다 올렸다고 알리면 일지로 나누고 저장합니다

- 형식은 `csv` · `txt` · `docx` · `pdf`, 크기는 20MB까지입니다
- 2번까지 하고 3번을 하지 않은 업로드는 하루 뒤 새벽에 파일과 함께 지웁니다

## 2. 일지로 나누기

파일 하나(원본 기록)를 일지 여러 건으로 나눕니다.

- **날짜로 시작하는 줄이 새 일지의 시작입니다.** `2026-11-08` · `2026.11.08` · `11/8` 모양을 읽고, 다음 날짜 줄까지가 한 일지입니다
- `11/8`처럼 연도가 없으면 올해로 봅니다. `1/3 정도`처럼 분수로 보이는 것은 날짜로 보지 않습니다
- 날짜가 하나도 없으면 파일 전체가 일지 한 건이고, 날짜는 파일명(`1108_관찰일지.txt` 등)에서, 그것도 없으면 올린 날로 정합니다
- `docx` · `pdf`는 첫 날짜 앞의 머리말(문서 제목 등)을 버립니다
- 파일명에 명부의 아이 이름이 하나만 들어 있으면 매칭의 힌트로 남깁니다

**한도** — 넘으면 저장하지 않고 거절합니다.

- 파일 하나에서 나온 일지 500건, 일지 하나 5,000자
- 서버 전체에서 동시에 나누는 업로드 2개, 기다릴 수 있는 업로드 4개 (넘으면 `429 RAW_RECORD_UPLOAD_BUSY`)
- 기관마다 AI 처리 줄(매칭 · 검증 · 요약 대기와 처리 중)에 1,000건 (넘으면 `429 AGENT_QUEUE_FULL`)

## 3. 매칭 — 누구 것인가

기관 명부에서 **보호자 동의가 살아 있는 아이**만 후보로 AI에 보냅니다.

| AI 판정 | 일지가 가는 곳 |
| --- | --- |
| `auto` | 검증 대기 (`MATCHED`) |
| `review` · `multi` · `unmatched` | 선생님 확인 (`MATCH_REVIEW`) |
| AI가 멈춤 | 매칭 대기로 되돌려 다시 시도. 여러 번 이어지면 선생님 확인 (`FAILED`) |
| AI 응답이 잘못됨 | 선생님 확인 (`FAILED`) — 선생님이 직접 아이를 고를 수 있습니다 |
| 일지가 너무 김 | 멈춤 (`SYSTEM_ERROR`) — AI에 보내지 않습니다 |

**선생님이 할 일** — 확인 필요 큐에서 아이를 고르거나(→ 검증 대기), 우리 기관 아이가 아니라고 뺍니다(→ `EXCLUDED`).

## 4. 검증 — 그대로 둬도 되나

| AI 판정 | 일지가 가는 곳 |
| --- | --- |
| `PASS` · `REVIEW` | 요약 대기 (`VALIDATED`). `REVIEW` 사유는 1차 검토에서 보여 줍니다 |
| `BLOCK` | 선생님 확인 (`VALIDATION_BLOCKED`) — 요약으로 넘기지 않습니다 |

**선생님이 할 일** — 수정 요청 큐에서 본문을 고쳐 다시 검사하거나(→ 검증 대기로 돌아감), 이 기록을 보류합니다(→ `VALIDATION_HELD`).

## 5. 요약 — 하루치 한 편

같은 **아이 × 날짜 × 기관** 묶음을 한 편으로 요약합니다. 묶음은 아래가 모두 맞을 때 집습니다.

- 같은 기관 · 같은 날짜에 아직 매칭이나 검증 중인 일지가 없을 것 (늦게 끝난 일지가 빠진 요약을 막습니다)
- 자동 요약(`SUMMARY_AUTO_RUN`, 기본 켜짐)이면 그 기관에 동의가 있는 아이, 꺼져 있으면 선생님이 [요약]을 누른 묶음

요약이 끝나면 일지는 1차 검토 대기(`GATE1_PENDING`)가 됩니다. 승인 전에 같은 묶음에 일지가 더 오면 기존 일지와 함께 다시 요약합니다.

**요약 실패** — 모델이 쓴 문장이 전부 근거 대조에서 떨어지면 `SUMMARY_FAILED`가 됩니다.
선생님이 요약 실패 목록에서 다시 요약하거나(→ 요약 대기), 요약 없이 마무리합니다(→ `COMPLETED`).

## 멈춘 일지

코드 버그나 AI 계약 위반으로 처리할 수 없으면 `SYSTEM_ERROR`가 되고, 어느 단계에서 왜 멈췄는지 남깁니다.
선생님 화면에서는 "관리자 확인 필요"로 보입니다. 원인을 고친 뒤 [운영 스크립트](../../backend/scripts/README.md#시스템-오류로-멈춘-일지-되돌리기)로 다시 처리하게 합니다.

- 앱이 처리 중에 죽어 `MATCHING` · `VALIDATING` · `SUMMARIZING`에 남은 일지는 워커가 다시 켜질 때 앞 단계로 되돌립니다
- AI 서버가 멈추면 워커는 재시도한 뒤 일지를 되돌려 두고, 기관 화면에 AI 장애 안내가 뜹니다

---

## 일지 상태

| 상태 | 뜻 |
| --- | --- |
| `PENDING` → `MATCHING` | 매칭 대기 → 매칭 중 |
| `MATCHED` → `VALIDATING` | 검증 대기 → 검증 중 |
| `VALIDATED` → `SUMMARIZING` | 요약 대기 → 요약 중 |
| `GATE1_PENDING` | 1차 검토 대기 (이후는 검토 도메인) |
| `MATCH_REVIEW` · `FAILED` | 매칭 — 선생님 확인 필요 |
| `VALIDATION_BLOCKED` · `VALIDATION_HELD` | 검증 — 막힘 · 보류 |
| `SUMMARY_FAILED` | 요약 실패 — 다시 요약하거나 마무리 |
| `EXCLUDED` · `COMPLETED` | 끝 — 우리 기관 아이 아님 · 처리 끝 |
| `SYSTEM_ERROR` | 관리자 확인 필요 |

## API · 테이블 · 코드

**API** (`/api/v1`, 기관 담당자만)

- `/raw-records` — 업로드 3단계 · 원본 기록 목록과 단건 · 파일별 처리 현황(`/progress`)
- `/matching-queue` — 확인 필요 큐 · 아이 확정 또는 제외(`/{id}/resolve`)
- `/validation-results` — 수정 요청 큐 · 보류(`/{id}/resolve`) · 고쳐서 다시 검사(`/{id}/revise`)
- `/summaries/run` — 요약 요청 · `/summaries/failed` — 요약 실패 목록 · 다시 요약 · 마무리

요청 · 응답 필드는 Swagger에 있습니다.

**테이블** — `raw_record_upload` · `raw_record` · `journal_entry` · `matching_result` · `validation_result` · `summary_result` · `summary_run_request` ([db/schema.md](../db/schema.md))

**코드** — `backend/.../service/record` (업로드 · 나누기) · `service/matching` · `service/validation` · `service/summary` (워커) · `domain/record/JournalEntry.java` (상태 변화)
