# 실제 데이터 점검 — 매칭 → 검증 → 요약 → 인사이트

실제 관찰일지(가명 처리)로 AI 에이전트 네 개를 **BE 없이 차례로** 돌려 보고, 결과를 HTML 보고서로 남깁니다.
합성 세트로는 보이지 않던 실제 기록의 문제(긴 일지, 비고 칸, 지저분한 말투, 드문 기록)를 찾는 것이 목적입니다.

> ⚠️ **데이터는 이 폴더에 없습니다.** 실제 아동 기록이라 레포에 올리지 않습니다.
> 스크립트만 커밋하고, 데이터·결과는 git-ignored 폴더 `AI/evals/generated/real/` 에 둡니다.

| `test.json` | 테스트용 실제 일지 32건 (8·9·11·12월) — **블라인드, 이 스크립트로 열지 않음** |

| `synthetic_school_dev.json` | 가상 학교 일지 20건 (4~6월) |
| `synthetic_school_answer.json` | 정답표 — 찾아야 할 패턴 14개 + 묶으면 안 되는 기록 12개 |

- 실제 기록은 센터 한 곳뿐이라 기관 간 차이를 볼 수 없어서, 같은 아동의 **학교 기록을 가상으로** 만들었습니다 (`"source": "synthetic"`).
- 가상 학교 일지는 두 종류를 섞었습니다. **센터 기록과 이어지는 기록**(같은 상황, 다른 대처)과 **학교에서만 있었던 활동**(급식·미술 등, 인사이트에 쓰이면 안 됨)입니다.
- 데이터 파일은 AI 담당자에게 따로 받습니다. 나누는 기준과 증강 규칙은 노션 "실데이터 활용 계획"을 봅니다.

## 실행

`AI` 폴더에서, `.venv` 를 켜고 `.env` 에 Luna 설정이 있는 상태로 돌립니다. AI 서버는 켜지 않아도 됩니다.

```bash
# 한 아동, 1월 (실제 센터 + 가상 학교) — 약 3분
python evals/scripts/real/run_real.py --months 01 --child 아동이름

# 1월 전체 아동
python evals/scripts/real/run_real.py --months 01

# 4~6월, 가상 학교 일지 20건과 함께
python evals/scripts/real/run_real.py --months 04,05,06 --school synthetic_school_dev.json
```

| 옵션 | 기본값 | 뜻 |
| --- | --- | --- |
| `--months` | `01` | 돌릴 달 (쉼표로 여러 달) |
| `--child` | 전체 | 한 아동만 |
| `--school` | `synthetic_school_demo.json` | 함께 넣을 가상 학교 일지 |
| `--window` | `30` | 인사이트 기간(일). 30이면 월 단위, 7이면 주 단위 |

끝나면 `AI/evals/generated/real/runs/` 에 `run_….json` 과 `run_….html` 이 생깁니다. **HTML 을 브라우저로 열어 봅니다.**

### 스크립트가 하는 일

```
일지마다    ① 매칭   이용자명 칸을 표지 힌트로 주고, 맞는 아이를 골랐는지 확인
            ② 검증   매칭이 고른 아이를 대상으로 판정
묶음마다    ③ 요약   아이 × 날짜 × 기관. BLOCK 일지는 넣지 않음 (BE 와 같음)
기간마다    ④ 인사이트  아이 × 30일. 두 기관 모두 동의한 것으로 둠
보고서      일지별 매칭·검증 / 요약 / 인사이트 카드 / 정답표 채점
```

- 명부는 데이터의 아동 전체입니다. 생년월일은 가짜입니다.
- 업로드할 때처럼 비고는 본문 뒤에 `비고: …` 로 붙입니다.
- Luna 가 빈 응답·시간 초과를 내면 같은 입력으로 **3번까지 다시** 부릅니다. 그래도 실패하면 멈추지 않고 보고서에 실패로 남깁니다.
- 기간을 BE(7일)와 다르게 30일로 두는 이유: 실제 기록은 아동 한 명이 한 주에 일지 2건 이상인 경우가 9%뿐이라, 7일로는 채점할 인사이트가 거의 나오지 않습니다.

### 보고서 읽는 법

| 칸 | 뜻 |
| --- | --- |
| 매칭 `auto` | 자신 있게 그 아이로 정함. ❌ 가 붙으면 다른 아이로 정한 것 |
| 검증 `REVIEW` | 교사 확인 필요. 막힌 것이 아님 |
| 검증 `BLOCK` | 요약으로 넘어가지 않음. 사유와 가리킨 곳을 꼭 봅니다 |
| 인사이트 "기관 간 차이" | 근거가 두 기관 이상 (코드가 계산) |
| 정답표 "관계없는 기록을 묶은 것" | 학교에서만 있었던 활동이 근거로 쓰였으면 억지로 묶은 것 |

보고서 맨 위와 터미널 끝의 **v1 비교** 줄은 v1 뒤에 고친 것이 효과가 있었는지 보는 숫자입니다 (판정에는 쓰지 않음).

| 숫자 | 뜻 |
| --- | --- |
| 요약할 내용 없음 | `no_content` 로 끝난 요약 묶음 수 |
| 하루 기록 하나로 만든 인사이트 | 근거 일지의 (날짜, 기관)이 한 종류뿐인 인사이트. 0 이어야 함 |
| 건강관리기록 · 진단명 | 검증 사유별 건수. 일상 건강 기록은 건강관리기록(REVIEW)으로 가야 함 |
| '~니다' 말투 | "~니다." 로 끝나는 문장이 있는 요약·인사이트 수. 0 이어야 함 |

## 기록

### v1 — 1월, 아동 A 한 명 (2026-10-28)

실제 센터 일지 5건 + 가상 학교 일지 4건 (센터와 이어지는 3건, 학교에서만 있었던 활동 1건).

| 단계 | 결과 |
| --- | --- |
| 매칭 | 9/9 정답 (모두 `auto`) |
| 검증 | PASS 8 · REVIEW 1 · BLOCK 0. REVIEW 는 위험행동표현 (몸을 부딪히며 고함 — 기준대로) |
| 요약 | 9/9 성공 (1건은 첫 호출에서 Luna 빈 응답 → 다시 불러 성공) |
| 인사이트 | 2개, 둘 다 기관 간 차이. 첫 호출 실패 → 다시 불러 성공 |
| 정답표 | **패턴 2/2 찾음**, 관계없는 기록을 묶은 것 **0건** |

**잘 된 것**
- 같은 날 고친 검증 과탐(주인공 이름을 개인정보로 봄)이 다시 나오지 않았습니다. 이름이 든 일지 9건 모두 BLOCK 없음.
- 핵심 패턴을 찾았습니다. "휴대폰을 바로 쓸 수 없을 때 센터에서는 울음·뛰기, 학교에서는 그림 시간표 카드로 진정"을 두 기관 근거로 묶었습니다.
- 학교에서만 있었던 미술 활동(관계없는 기록)은 근거로 쓰지 않았습니다.

**아쉬운 것**
- **두 번째 인사이트의 초점이 정답과 다릅니다.** 정답표는 "체육 시간에는 두 기관 모두 휴대폰을 찾지 않고 적극적"인데, 인사이트는 "차례·규칙을 따르지 않고 공을 모아 다님"을 묶었습니다. 기록에 있는 사실이라 틀리지는 않지만, 휴대폰 패턴과의 대비를 놓쳤습니다.
- **대처 하나에 두 대처가 섞였습니다.** "반응하지 않음"과 "과자·멸치"가 한 대처의 결과로 묶여, 센터의 핵심 대처(과자·멸치 → 안정)가 따로 보이지 않습니다.
- **가상 학교 일지가 얇습니다.** 학교 기록이 한두 장면뿐이라, 학교 쪽 인사이트 문장도 얇습니다. 다음 판에서 학교 일지를 실제 센터 일지만큼 길게 씁니다.
- **요약 말투가 섞입니다.** 9건 중 2건이 "~했습니다"(합쇼체)로, 나머지 "~했다"와 다릅니다 (요약 CRITERIA §3 기록체).
- **Luna 호출이 불안정합니다.** 요약 1건, 인사이트 1건이 첫 호출에서 실패했습니다. 인사이트는 claims 25개로 입력이 길어 60초 제한에 걸렸을 가능성이 있습니다.

**이 결과로 말할 수 없는 것**: 아동 한 명, 패턴 2개입니다. 성능 숫자가 아니라 "끝까지 돈다, 크게 틀리지 않는다"는 확인입니다.

### v1 — 4~6월, 아동 12명 (2026-10-28)

실제 센터 일지 48건 + 가상 학교 일지 20건 (아동 5명, 이어지는 기록 8건 · 학교에서만 있었던 활동 12건).

| 단계 | 결과 |
| --- | --- |
| 매칭 | 68/68 정답 (모두 `auto`) |
| 검증 | PASS 43 · REVIEW 17 · BLOCK 8 |

| 패턴 | 놓친 이유 |
| --- | --- |

| P6 | 인사이트는 나왔지만 **센터 일지 하나**만으로 만들고 학교 일지를 쓰지 않음 |

**검증 — BLOCK 8건 중 6건이 일상 건강 기록**
- "코로나 확진" 3건, "비염 연고", "연고 도포", "약물 복용확인"이 진단명으로 BLOCK. 판정 기준이 진단명에 "치료, 복용 약 등 의료 정보"를 넣고 있어 **기준대로의 판정**입니다.
- 실제 기록에는 이런 일상 건강 기록이 많아서, 기준대로면 평범한 하루 기록이 요약에서 통째로 빠집니다. **기준을 좁힐지 팀과 정할 일**입니다 (예: 진단명·장애명은 BLOCK, 일상적인 약·연고·감기는 REVIEW).
- 다른 아동의 코로나 확진("활동보조인의 코로나 확진")도 BLOCK. 진단명은 귀속 검사를 하지 않는 유형이라 그렇습니다.
- 위험행동표현 REVIEW 중 과탐으로 보이는 것: "나가려는 횟수가 줄었다"(좋아진 기록), "친구 손을 잡아 당기며 율동에 참여", "안전에 유의하였다"(교사 조치). REVIEW 라 막지는 않습니다.

**인사이트 — 하루 기록 하나로 만든 인사이트 4개**
- 17개 중 4개가 **일지 한 건**만 근거로 했습니다. 실제 일지가 길어서 한 건에서 문장이 여러 개 나오고, 지금 규칙은 "서로 다른 문장 2개"면 성립하기 때문입니다 (`COUNT_DISTINCT_DATES = False`).
- "요약 한 편에서 그대로 나올 수 있는 문장이면 인사이트가 아니다"(CRITERIA §1)에 어긋납니다. P6 를 놓친 것도 이것입니다.
- 이 4개는 내용도 약했습니다 (인사에 손을 흔듦, 사다리 오르내리기 등 하루의 관찰 다시 말하기).

**말투가 섞입니다**
- 요약 60건 중 6건, 인사이트 일부가 "~했습니다"(합쇼체). 나머지는 "~했다".

**잘 된 것**
- 정답표의 기관 간 패턴을 찾은 6개는 모두 두 기관 근거를 함께 묶었고, 학교에만 있던 대처(놀이로 걸음 바꾸기, 스피커 멀리 두기, 쉬는 의자, 체크표 스티커)를 대처와 결과로 정확히 옮겼습니다.
- 학교에서만 있었던 활동 12건은 한 번도 근거로 쓰이지 않았습니다.
- 매칭은 68건 모두 맞았습니다. 일지 본문에 아이 이름이 없어도 이용자명 칸(표지 힌트)으로 찾았습니다.

**다음에 고칠 것 (우선순위)**
1. 인사이트 근거를 "서로 다른 날 **또는** 서로 다른 기관"으로 세기 — 하루 일지 하나로 만든 인사이트를 막되, 같은 날 두 기관 비교는 살림
2. 검증 진단명 기준 범위 — 팀 결정
3. 요약·인사이트 말투를 "~했다"로 통일
4. 인사이트 Luna 응답 실패 — 입력이 긴 경우 제한시간 확인

- **입력이 길면 인사이트가 실패합니다.** 1월 아동 A 는 문장 35개에서 3번 모두 빈 응답, 4~6월은 19개에서 1번 빈 응답, v1 1월은 25개에서 1번 실패였습니다. 17개 이하는 모두 한 번에 성공했습니다. 길이와 함께 늘어나지만 **원인은 확인하지 않았습니다** — 모델이 답을 쓰기 전에 토큰 한도에 걸렸는지(`finish_reason`)를 찍어 봐야 압니다. 1월 아동 A 의 v1 패턴 2개는 이번에 채점하지 못했습니다.
- **건강 기록만으로 인사이트가 만들어졌습니다.** 한 아동의 코로나 확진 중·확진 후 증상 두 기록을 묶은 인사이트가 나왔습니다. 건강관리기록이 REVIEW 로 요약까지 가면서 생긴 것으로, 다음 돌봄에 쓸 패턴이 아니고 다른 기관에도 공유됩니다.
- **P6 를 놓쳤습니다.** "짜증·울음 때 안아 주면 두 기관 모두 빠르게 안정" (같은 대처, 같은 결과). 문장 4개 입력에서 인사이트 0개로, "같은 행동이 겹치기만 해서는 쓰지 않는다"(`NEED_DIFFERENCE`)가 두 기관에서 통한 같은 대처까지 막은 것으로 보입니다.
- 기록에 없는 것을 말하는 문장이 하나 있었습니다 ("활동 참여 여부는 기록되지 않았다").

**다음에 고칠 것 (우선순위)**
1. 인사이트 빈 응답 — `finish_reason`·토큰 사용량을 찍어 원인 확인 후, 한도 문제면 입력을 나누거나 줄임
2. 질병·약·증상만으로는 인사이트를 만들지 않도록 쓰는 원칙 추가
3. `NEED_DIFFERENCE` 를 "두 기관에서 같은 대처가 통한 경우"는 쓰도록 다듬기

### v3 — Luna 빈 응답 원인 확인과 대처 (2026-10-30)

v2 에서 남은 문제 셋을 고치면서, 같은 두 범위로 설정 두 가지를 비교했습니다.

**빈 응답의 원인을 확인했습니다**
- 빈 응답일 때 `finish_reason` 을 찍어 보니 3번 모두 `length`, 출력 2000 토큰이 **전부 생각(reasoning)** 이었습니다. 답 쓸 자리가 남지 않은 것입니다.
- 출력 한도를 늘리려 했지만 Luna 프록시가 막습니다. `max_completion_tokens` 4000·8000, `max_tokens` 8000 이 모두 400 ("스트리밍이 아닌 응답은 2000 토큰 상한"). `reasoning_effort: low` 는 받습니다.
- 요약도 가장 긴 하루 일지에서 같은 실패가 났습니다.

**두 설정을 비교했습니다**

| 4~6월, 아동 12명 | v2 (기본) | v3-A 항상 low | **v3-B 넘칠 때만 low (채택)** |
| --- | --- | --- | --- |
| 정답 패턴 | 9/10 | 7/10 | **10/10** |
| 기관 간 인사이트 | 9 | 7 | **11** |
| 요약 문장 | 216 | 192 | 213 |
| 실패 | 인사이트 1회 | 0 | **0** (요약 5회 넘침 → low 로 살림) |
| 관계없는 기록 묶음 | 0 | 0 | **1** |
| 인사이트 수 | 15 | 13 | 18 |

| 1월 아동 A | v2 | v3-A | v3-B |
| --- | --- | --- | --- |
| 요약 | 9/9 | 9/9 | 9/9 |
| 인사이트 | 실패 (3번 빈 응답) | 1~2개 (P1 · P2 / P1) | 1개 (P1), 넘침 1회 → low |

- 항상 low 로 두면 실패는 사라지지만 기관을 가로지른 비교가 약해졌습니다 (P7·P14 를 잃음, 학교 근거가 빠진 인사이트).
- 그래서 **보통은 모델 기본값으로 생각하고, 답이 비었고 `finish_reason=length` 일 때만 low 로 한 번 더** 부릅니다 (요약·인사이트 `ask_json`, `LUNA_REASONING_EFFORT_ON_OVERFLOW`).
- 긴 입력은 low 로 살리는 대신 품질이 떨어집니다. 1월 아동 A(30일, 문장 30개 안팎)가 그 경우입니다. 실제 서비스는 7일 단위라 이렇게 긴 입력은 드뭅니다.

**v2 의 다른 두 문제**
- 건강 기록만으로 만든 인사이트: 쓰는 원칙 `DROP_HEALTH_ONLY` 추가 후 **v3-A·B 모두 사라짐** (인사이트 CRITERIA v0.9.4).
- P6 (두 기관 모두 안아 주면 안정): `NEED_DIFFERENCE` 에 "두 기관에서 같은 대처가 같은 결과" 를 넣어 봤지만 v3-A 에서 찾지 못해 **되돌렸습니다**. v3-B 에서는 원래 문장으로 찾았습니다 — 실행마다 흔들리는 범위로 보입니다.

**아쉬운 것**
- 관계없는 기록을 처음 묶었습니다. 학교 줄넘기와 센터 노래·신체놀이를 "몸을 쓰는 활동" 으로 묶었습니다 (`SAME_SITUATION` 위반).
