# 매칭 판정 기준

어떤 상황에서 `auto` / `review` / `multi` / `unmatched` 가 나오는지를 정한 문서다.
**이 문서가 기준이고 `config.py` 가 그것을 따른다.** 둘이 어긋나면
`evals/scripts/matching/test_criteria_sync.py` 가 깨진다.

> 2026-10-02 에 노션에서 레포로 옮겼다. 검증 에이전트가 판정 기준을 레포에 두고
> 동기화 테스트로 묶어둔 것과 같은 방식이다. 코드를 읽다 "왜 review 지?" 를
> 찾으려고 레포를 떠나지 않게 하려는 것이다.

---

## 0. 네 가지 상태

사람이 무엇을 해야 하는가로 이름을 지었다. 모델이 얼마나 확신하는가가 아니다.

| status | 뜻 | 교사가 할 일 |
| --- | --- | --- |
| `auto` | 확정 | 없음 |
| `review` | 후보는 하나인데 근거가 약함 | "이 아이 맞나요?" 확인 |
| `multi` | 후보가 둘 이상 | `candidates` 중에서 고름 |
| `unmatched` | 명부에서 못 찾음 | 이름으로 검색하거나 아이를 등록 |

`auto` 는 **사람 확인을 건너뛴다.** 그래서 여기서 틀리면 다른 아이의 기록이
부모에게 간다. 다른 어떤 지표보다 **오매칭 0건**이 우선이다.

---

## 1. 판정 순서

위에서부터 먼저 걸리는 것이 이긴다.

```
0  근거가 글자로 아무것도 없음            → unmatched
0  표지 이름이 명부에 없고 본문에도 없음    → unmatched
1  두 아이가 대등하게 등장 (co_mention)   → multi
2  자동 확정 조건을 모두 만족             → auto
3  후보 하나, 근거는 약함                 → review
4  후보 둘 이상                          → multi
5  후보 없음                             → unmatched
```

**0번이 모델보다 앞에 있는 것이 중요하다.** 근거가 없으면 모델에게 묻지 않고
끊는다. `"우리 반 막둥이가 새 신발을 자랑함"` 같은 기록에서 모델은 근거가 없어도
명부의 아무 아이를 골라 confidence 0.86 을 준다. 모를 때 모른다고 하는 것이 이
단계의 정답이다.

---

## 2. 자동 확정 조건

**모델이 매긴 confidence 숫자를 보지 않는다.** 네 가지가 모두 참일 때만 `auto` 다.

```
1. 후보가 정확히 한 명이다
2. 근거가 글자로 존재한다 — **고른 아이 본인의** 이름이 본문에 있거나
   표지가 그 아이를 뒷받침한다
3. 근거를 부정하는 신호가 없다 — 대등 언급이 아니다
4. 판단에 쓴 정보가 검증되었다 — 모델 호출 성공, 명부 안의 ID
```

### 2번은 "누군가" 가 아니라 "그 아이" 다

2026-10-03 멘토 리뷰 전까지 2번은 `has_exact`, 즉 **"명부의 누군가 이름이
본문에 있다"** 였다. 그래서 아래가 자동 확정으로 나갔다.

```
본문   "지후가 블록을 쌓았다"        지후 = A
모델   B 를 선택                     B 의 이름은 본문 어디에도 없다
판정   auto                          ← A 의 이름이 B 의 근거가 됐다
```

**다른 아이의 이름은 근거가 아니라 경고 신호다.** 본문에 A 가 있는데 모델이
B 를 골랐다면, 그것은 근거가 생긴 것이 아니라 모델과 본문이 어긋난 것이다.
`REQUIRE_WINNER_NAME_FOR_AUTO` 로 고정했고, 코드는 `exact_child_ids`
(코드가 글자로 확인한 ID 만) 를 본다.

`mentioned_child_ids` 를 쓰지 않는 이유가 있다 — 그 목록에는 `llm_judge` 가
대등 언급으로 보고한 ID 가 더해진다. 모델이 "얘도 나왔다" 고 말한 것을
자동 확정의 근거로 쓰면 1번 문단으로 되돌아간다.

### 왜 숫자를 안 보나

모델의 confidence 는 실행마다 크게 흔들린다. **같은 입력 5회에 0.72~0.98** 이
나오고, `seed` 를 넣어도 고정되지 않는다 (2026-09-18 확인). 반면 "누구를
골랐는가" 는 안정적이다.

흔들리는 값에 사람 확인 여부를 맡기면 **같은 기록이 어제는 자동 확정되고 오늘은
확인 큐로 간다.** 그래서 2026-09-18 에 임계값 판정을 불리언 규칙으로 바꿨다.

`TAU_AUTO` 는 아직 `config.py` 에 남아 있지만 `AUTO_GATE = "structural"` 인 동안
자동 확정에 쓰이지 않는다. `TAU_REJECT` 는 계속 쓰인다 — 후보로 칠 하한선이다.

### 자동 확정을 되돌리는 신호

위 조건을 지나도 아래에 걸리면 `review` 로 내린다.

| 신호 | 왜 |
| --- | --- |
| `hint_mismatch` | 표지와 다른 아이로 판단했다. 둘 중 하나는 틀렸고 사람이 봐야 한다 |
| `llm_off_roster` | 모델이 명부에 없는 ID 를 줬다. 규칙을 어긴 응답이라 다른 값도 못 믿는다 |
| `llm_error` | 모델 호출이 실패했다. 애매해서 불렀는데 반쪽으로 통과시킬 수 없다 |

## 3. 이름을 찾는 규칙

### 정확 일치

이름 **앞뒤가 모두 경계**일 때만 인정한다. 경계는 한글이 아닌 문자(공백·구두점·
문장 끝)다.

```
명부에 '은하' 가 있고 본문이 "은하수 사진을 보며 별을 그렸다"
→ 경계 검사가 없으면 은하의 기록으로 자동 확정된다
```

### 오타 (퍼지)

편집거리 유사도가 **0.6 이상**이면 후보로 본다. 한글 3글자 이름에서 한 글자가
다르면 정확히 0.667 이 나오기 때문이다. 세 글자 중 한 글자만 같으면 0.333 이라
걸러진다.

**정확 일치보다 한 단계 엄격하게 본다** — 이름 뒤에 **조사가 붙어 있어야** 한다.
경계 검사만으로는 진짜 오타와 문장 조각이 갈리지 않는다. 둘 다 유사도 0.667 이고
경계도 통과한다.

```
"임유젼이"   → '이' 주격 조사    진짜 오타로 본다
"이동함."    → '.' 문장부호      '이동현' 과 우연히 비슷할 뿐
"제안하자 "  → ' ' 공백          '안하윤' 과 우연히 비슷할 뿐
```

> ⚠️ **알려진 한계** — 이름 뒤에 쉼표가 오면 퍼지 매칭이 거부된다.
> `"허시언, 비눗방울 놀이 중…"` 같은 표기가 실제 일지에 흔한데 조사가 아니라
> 못 잡는다. 2026-09-30 홀드아웃에서 확인됐고 아직 고치지 않았다.

### 성을 뗀 이름

교사는 `"백지안이가"` 보다 `"지안이가"` 라고 쓴다. 편집거리로는 이것이 문장 조각
오탐과 구별되지 않아, 성을 뗀 이름이 경계까지 맞게 등장하는지를 따로 본다.

```
백지안 → '지안'   "지안이가" 에 있음      ✓
정하윤 → '하윤'   "정교하게" 에 없음      ✗
```

**전체 이름이 등장한 것이 아니므로 정확 일치로 치지 않는다.** 모델 건너뛰기
경로에 들어가지 못하고, 자동 확정에도 표지 뒷받침이 필요하다.

> ⚠️ **알려진 한계** — 그래서 본문에 **이름만** 쓰인 기록은 `auto` 가 되지 않는다.
> 실제 일지는 성을 안 쓰는 쪽이 정상이라 영향이 크다. 2026-09-30 홀드아웃에서
> 10건 중 4건이 이 경로로 `review` 가 됐다.

---

## 4. 표지 힌트

파일 이름에서 뽑은 아동 이름이다. **정답이 아니라 1차 단서다.**

| | |
| --- | --- |
| 힌트가 다른 근거와 일치 | 점수를 조금 얹는다 |
| 힌트만 있고 본문에 근거 없음 | 사람 확인으로 보낼 수 있는 바닥 점수를 깔아준다 |
| 힌트 이름이 명부에 없음 | **미등록 아동**으로 보고 `unmatched` |

**실제 관찰일지는 표지에 이름이 있고 본문에는 없는 것이 정상이다.** 테스트
1,070건 중 본문에 이름이 등장하는 것은 61건뿐이었다. 그래서 "본문에 이름이 없으면
`auto` 금지" 로 두면 확인 큐가 100% 가 된다.

**힌트가 빠지면 자동 확정률이 89% → 4% 로 떨어진다.** 백엔드가 요청에 반드시
실어야 한다.

---

## 5. 동명이인

이름이 같으면 본문만으로는 구별할 방법이 없다. **모델이 한 명을 골라도 그것은
판단이 아니라 임의 선택이다.** 생년월일 같은 구분 근거가 있을 때만 한 명으로
좁히고, 없으면 둘 다 남겨 `multi` 로 보낸다.

---

## 6. 두 아이가 함께 나오는 기록

`co_mention` 은 **"이 기록이 누구의 관찰 기록인가"** 를 가르는 판단이다.

```
다른 아이가 등장해 무언가를 하더라도, 그 행동이 주인공을 향하거나
주인공 활동의 일부이면 co_mention 은 false 다
```

| | |
| --- | --- |
| `ambiguous_identity` | 누구 것인지 모르겠다 → "골라주세요" |
| `co_mention` | 두 아이가 대등하게 나온다 → "누구 기록으로 저장할까요" |

한 기록을 여러 건으로 쪼개는 것은 MVP 범위가 아니라서, 사람에게 넘기는 쪽을
택했다.

> ⚠️ **알려진 한계** — 조연이 **독립적인 자기 동작**을 하면 대등 언급으로 잘못
> 본다. 2026-09-30 홀드아웃에서 5건 중 2건이 그랬다.
> 규칙이 "조연이 주인공을 향하는가" 로 쓰여 있는데, 실제 기준은 **"둘 다 관찰
> 대상인가"** 다. 코드보다 이 문장을 먼저 고쳐야 한다.

## 7. 측정

| 지표 | 기준 |
| --- | --- |
| **오매칭** | **0건.** 비율이 아니라 건수로 본다 |
| 오탐 (명부에 없는 아이를 특정) | 0건 |
| 정답 도달률 | `multi` 의 후보 안에 정답이 있으면 도달한 것으로 센다 |

**점수 하나만 보지 않는다.** 규칙 기준선과 나란히 채점한다 — 2026-09-16 에 자체
채점 96% 가 나왔을 때 표지만 읽는 세 줄짜리 코드가 100% 를 받았다. 절차는
[HOLDOUT.md](../evals/scripts/matching/HOLDOUT.md) 에 있다.

### 자동 확정 조건은 홀드아웃으로 재지 않는다

모델이 어느 아이를 고르는지가 실행마다 흔들려서, 게이트를 고쳐도 결과 차이가
잡음에 묻힌다. 2026-10-03 에 1,050건을 전후로 돌렸더니 달라진 3건이 **전부**
모델이 다른 아이를 고르거나 대등 언급 판단을 뒤집은 경우였고, 게이트 때문에
달라진 건은 0건이었다.

그래서 모델 응답을 고정해두고 게이트만 보는 테스트를 따로 둔다 —
`evals/scripts/matching/test_auto_gate.py`. LLM 을 부르지 않는다.
