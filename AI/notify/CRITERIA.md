# 알림 발송 기준

> `AI/notify/` 가 무엇을 내보내고 무엇을 막는지. 코드(`config.py` · `nodes.py`)가 이 문서를 따른다.
> 설계 배경은 [AGENTIC.md](../AGENTIC.md) §7~8.

## 0. 알림은 판정이 아니다

무엇을 보낼지는 이미 정해져 있다 — **Gate 2 에서 교사가 승인한 인사이트**다.
여기서 새로 판정하지 않는다. 하는 일은 둘이다.

1. 교사용 표현을 보호자용으로 **다시 쓴다** (모델)
2. 다시 쓴 글이 승인된 내용 안에 있는지 **대조한다** (코드)

## 1. 메일은 되돌릴 수 없다 — 그래서 통째로 막는다

요약은 근거 없는 문장만 빼고 나머지를 낸다 (`summary/CRITERIA.md §2`).
메일은 **한 줄이라도 걸리면 전체를 막는다** (`config.BLOCK_WHOLE_MAIL`).

까닭은 둘이다.

- 한 줄 빠진 메일은 **교사가 승인한 적 없는 조합**이다. 문맥이 끊긴 글이 나간다
- 보낸 뒤에는 되돌릴 수 없다. 요약은 교사가 Gate 1 에서 다시 보지만, 메일은 이미 받은편지함에 있다

## 2. 수신자는 계약에 없다

`NotifyInput` 에 이메일 주소가 없다. `child_id` 만 있고, 주소는 MCP 서버가 찾는다.

```
❌ send_email(to="parent@example.com", ...)
✅ send_email(child_id=12, ...)   ← 주소는 서버가 찾는다
```

`insight/tools.py` 의 `find_claims` 와 같은 원칙이다 — **모델은 무엇을 보낼지만 정하고,
어디로 갈지는 코드가 정한다.** 주소를 인자로 두면 모델 문맥에 주소가 들어오고,
그 순간 "모델이 지어낸 주소로 아이 기록이 나간다" 가 가능해진다.

같은 이유로 프롬프트에도, 로그에도 주소가 없다. 로그에는 **받는 사람 수만** 적는다.

## 3. 무엇이 걸리는가 — 네 가지

`nodes._line_reasons()` 가 줄마다 본다.

| 이유 | 언제 | 왜 |
| --- | --- | --- |
| `근거없음` | 줄이 `insight_index` 를 안 가리키거나 범위 밖이다 | 대조할 상대가 없으면 "통과했다" 고 말할 수 없다 |
| `숫자불일치` | 줄의 숫자가 그 인사이트에 없다 | 환각이 가장 눈에 띄는 자리다 |
| `기관불일치` | 줄이 말한 기관이 그 인사이트의 근거 기관에 없다 | 센터 기록뿐인데 "학교에서는" 을 붙이면 보호자가 사실을 잘못 안다 |
| `다른아이이름` | 다른 아이 이름이 메일 글자에 있다 | 메일은 기관 경계 밖으로 나가는 유일한 길이다 |
| `인사이트누락` | 승인된 인사이트가 메일에 통째로 빠졌다 | 한 줄이 빠지면 막으면서 한 건이 빠지는 것을 통과시킬 수 없다 |

`다른아이이름` 만 **인사이트가 아니라 메일 글자를 본다.** 모델이 어디서 가져왔든 나가면 안 된다.

### 제목도 본다

제목은 모델이 쓰는데 처음에는 검사에서 빠져 있었다 (리뷰 #430). **받은편지함 목록에 제일 먼저
보이는 글자라, 여기로 새면 열어 보지 않아도 샌다.**

본문과 기준이 하나 다르다 — 제목은 인사이트 하나를 가리키지 않으므로 숫자를 **승인된 내용 전부 +
기간 날짜**와 맞춘다. "김지후의 2026-04-01 ~ 2026-04-07 기록" 처럼 기간을 쓰는 것이 정상이다.

## 4. 끝나는 길은 셋이다

| 응답 | 뜻 | BE 가 할 일 |
| --- | --- | --- |
| `200 sent` · `200 nothing_to_send` | 나갔거나, 보낼 것이 없었다 | 끝 |
| `200 no_recipient` | 글은 통과했는데 **받을 사람이 없었다** | 끝. 장애가 아니다 |
| `200 blocked` | 근거 미달이다 | **교사 확인 큐로.** 재시도하지 않는다 — 같은 재료면 같은 결과다 |
| `503 llm_unavailable` | 모델 고장 | 재시도 |
| `503 delivery_failed` | 메일 서버 장애 | 재시도 |

`no_recipient` 를 `sent` 로 묶지 않는다 (리뷰 #430). 장애는 아니지만 **메일은 안 나갔다.**
합치면 BE 가 `SENT` 로 적고 교사는 "보냈다" 고 믿는데, 실제로는 아무에게도 안 갔다.

**근거 미달을 503 으로 올리면 BE 가 영원히 재시도한다.** 반대로 메일 서버 장애를
`blocked` 로 내리면 교사가 고칠 수 없는 것을 큐에서 본다. 요약의
`llm_unavailable` ↔ `no_grounded_claims` 와 같은 구분이다 (#148).

## 5. 같은 묶음은 한 번만

`notification_id` 가 멱등성 기준이다. 같은 값으로 다시 오면 보내지 않고
처음 `message_id` 를 그대로 돌려준다. BE 재시도가 보호자에게 메일 세 통이 되면 안 된다.

기록은 MCP 서버가 `evals/generated/notify/sent.json` 에 남긴다.
**본문은 남기지 않는다** — 아이 기록이다. 식별자와 받는 사람 수만 적는다.

구멍 둘을 막았다 (리뷰 #430).

- **동시 호출** — 보내기 전에 파일 락을 잡고 자리를 먼저 적는다. 안 그러면 같은 키가 동시에 두 번
  왔을 때 둘 다 "기록이 없다" 를 보고 각자 보낸다
- **보호자 여럿** — 한 명 보낼 때마다 적는다. 둘째 보호자에게 보내다 SMTP 가 끊겨도, 다시 부르면
  첫 보호자는 건너뛴다. 전에는 기록 없이 503 이 되어 첫 보호자가 두 통을 받았다

`delivered` 에는 주소가 들어 있어 도구 응답에서 가린다 — 모델 문맥에 주소가 들어가면 안 된다.

## 6. 코드가 막지 못하는 것

- **한글 수사.** `_DIGITS` 는 아라비아 숫자만 본다. 메일이 "세 번" 을 "다섯 번" 으로
  바꿔 써도 통과한다. 요약의 `_numbers` 가 보는 영역인데, 여기서 다시 구현하면
  두 벌이 갈라져 더 나쁘다
- **지어낸 사실 중 숫자·기관·이름이 아닌 것.** "많이 좋아졌어요" 처럼 재료에 없는
  판단은 코드가 못 잡는다. 프롬프트의 `GROUND_RULE` 이 막는 수밖에 없다
- **명부에 없는 아이 이름.** `other_child_names` 에 있는 이름만 본다. BE 가 안 보낸
  이름은 모른다 (요약·인사이트와 같은 한계)
- **말투.** 해요체로 썼는지 코드가 보지 않는다. 틀려도 메일은 나간다

- 보호자 이메일 수집 — #420
- 블라인드 측정. 근거 미달을 일부러 만든 세트로 **막히는 비율**을 재야 한다
